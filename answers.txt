1. Java là ngôn ngữ Pass-by-Value hay Pass-by-Reference
Trả lời: Java là ngôn ngữ lập trình Pass-by-Value (Truyền tham trị).

Đối với các kiểu dữ liệu nguyên thủy (primitive), Java truyền bản sao giá trị của biến.

Đối với các đối tượng (Object), Java truyền bản sao của tham chiếu (copy of the reference/memory address).

2. Tại sao sau khi gọi swap(jungleDVD, cinderellaDVD), tiêu đề của hai đối tượng vẫn giữ nguyên?
Giải thích: * Khi hàm swap(o1, o2) được gọi, Java tạo ra hai biến cục bộ o1 và o2. Hai biến này nhận bản sao địa chỉ vùng nhớ từ jungleDVD và cinderellaDVD.

Bên trong hàm, lệnh tráo đổi tmp = o1; o1 = o2; o2 = tmp; chỉ làm thay đổi địa chỉ mà hai biến cục bộ o1 và o2 đang nắm giữ.

Hành động này không hề tác động đến hai biến gốc ở hàm main. Sau khi hàm kết thúc, các biến cục bộ bị xóa bỏ, hai biến gốc vẫn trỏ về hai đối tượng cũ như ban đầu.

3. Tại sao sau khi gọi changeTitle(jungleDVD, cinderellaDVD.getTitle()), tiêu đề của JungleDVD lại bị thay đổi?
Giải thích:

Trong hàm changeTitle(dvd, title), biến dvd là một bản sao tham chiếu trỏ cùng tới một đối tượng jungleDVD trên bộ nhớ Heap.

Lệnh dvd.setTitle(title) sử dụng tham chiếu đó để truy cập trực tiếp vào vùng nhớ của đối tượng và thay đổi dữ liệu thuộc tính title tại đó.

Vì biến gốc jungleDVD ở hàm main cũng đang trỏ vào cùng vùng nhớ này, nên nó "nhìn thấy" sự thay đổi dữ liệu mà hàm đã thực hiện.
"Trong Java, do cơ chế Pass-by-Value, chúng ta không thể hoán đổi hai biến tham chiếu gốc. Để hoán đổi, chúng ta phải can thiệp vào các thuộc tính bên trong đối tượng thông qua Setter hoặc sử dụng một đối tượng bao ngoài (Wrapper Object)."
Mẹo trung gian: Thay vì truyền bản sao địa chỉ của viên kẹo (không tráo được), ta truyền bản sao địa chỉ của cái hộp.

Hành động trên Heap: Nhờ cái "bản sao địa chỉ hộp" đó, ta tìm được đến đúng vị trí của cái hộp thật trên bộ nhớ Heap. Tại đây, ta không tráo hai cái hộp, mà ta tráo nội dung bên trong cái hộp đó.

Chốt lại, JAVA luôn truyền pass-by-value

1. Compare Swing and AWT elements
Answer:
- AWT uses heavyweight components that depend more directly on the native operating system UI toolkit. Swing uses lightweight components written mostly in Java.
- AWT top-level container is Frame, while Swing top-level container is JFrame.
- AWT components are Label, TextField, Button, Panel. The corresponding Swing components are JLabel, JTextField, JButton, JPanel.
- In Swing, components should be added to the content pane of a JFrame instead of directly to the top-level container.
- Swing provides richer, more flexible components and supports pluggable look and feel.

2. NumberGrid ButtonListener
Answer:
- If a digit button is pressed, append that digit to the display text field.
- If the DEL button is pressed, remove the last character only when the display is not empty.
- If the C button is pressed, clear the whole display text field.

3. Painter eraser feature
Answer:
The eraser can be implemented like the pen. The difference is that the eraser draws small white circles, which have the same color as the drawing pane background. RadioButton controls in the same ToggleGroup are used so the user can select either Pen or Eraser.

4. Why should Cart use ObservableList for TableView?
Answer:
TableView observes ObservableList changes. When items are added to or removed from the cart, the TableView can update its displayed rows automatically. A normal ArrayList does not notify JavaFX controls about changes.

5. What happens when Aims is not updated to catch PlayerException?
Answer:
PlayerException is a checked exception because it extends Exception. If play() declares throws PlayerException and Aims does not catch or delegate it, the program will not compile. All calls to play() must be placed inside try-catch blocks or the calling method must also declare throws PlayerException.

6. PlayerException usage
Answer:
PlayerException is raised when a playable media has invalid length. DigitalVideoDisc.play() and Track.play() throw PlayerException when length is less than or equal to zero. CompactDisc.play() also checks the CD length and handles exceptions from each Track.

7. Media equals() rule
Answer:
Two Media objects are considered equal when they have the same title. The implementation should first check whether the object is a Media instance to avoid ClassCastException, and should compare titles in a null-safe way to avoid NullPointerException.
